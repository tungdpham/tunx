# Experimental Setup for Convergence & Numerical Equivalence Testing

This document details the configuration used to demonstrate correctness, numerical equivalence, and convergence across our evaluated models (ResNet50 and GPT-2 Small). It is specifically intended to validate that the custom engine ("TunX") replicates the standard PyTorch baseline precisely over extended training runs.

## 1. Testing Methodology

We employ a strict **multi-step trajectory matching** methodology to guarantee tensor-level and gradient-level equivalence over 1000 steps of training.

1.  **Strict Weight Initialization Matching**: A deterministic PyTorch model is initialized with a specific random seed. All model parameters are dumped to binary files. The TunX engine loads these exact weights at initialization.
2.  **Identical Input Pipelines**: To eliminate stochasticity from data loading or augmentations, the PyTorch reference script dynamically generates a sequence of 1000 input batches (and labels) using a fixed random seed. This exact trajectory of inputs is saved and directly consumed step-by-step by the TunX engine. 
3.  **Synchronized Optimizer**: Both frameworks use the same optimizer configuration (Adam) and apply exactly 1000 backward passes and parameter updates.
4.  **Multi-Seed Evaluation**: The entire 1000-step test is repeated across three distinct random seeds (`42`, `420`, `4200`) to guarantee that convergence equivalence holds across varying initializations and input distributions.

## 2. Model & Optimization Configurations

### ResNet-50 (ImageNet-100 configuration)
*   **Architecture**: ResNet-50 
*   **Input Shape**: `[Batch Size, 3, 224, 224]`
*   **Initialization**: Kaiming Normal (via PyTorch defaults) based on the specified run seed.
*   **Optimizer**: Adam
    *   Learning Rate: `1e-3`
    *   Betas: `(0.9, 0.999)`
    *   Epsilon: `1e-8`
    *   Weight Decay: `3e-4`
*   **Loss Function**: Cross-Entropy Loss
*   **Batch Size**: 8 (Evaluated over 1000 steps)
*   **Convergence Metric**: Top-1 Accuracy

### GPT-2 (Small)
*   **Architecture**: Transformer Decoder (12 Layers, 12 Heads, 768 Hidden Dim)
*   **Vocabulary Size**: 50,257
*   **Sequence Length**: 1024
*   **Input Shape**: `[Batch Size, 1024]`
*   **Initialization**: PyTorch Default Linear/Embedding initialization based on the specified run seed.
*   **Optimizer**: Adam
    *   Learning Rate: `1e-3`
    *   Betas: `(0.9, 0.999)`
    *   Epsilon: `1e-8`
    *   Weight Decay: `3e-4`
*   **Loss Function**: Cross-Entropy Loss
*   **Batch Size**: 8 (Evaluated over 1000 steps)
*   **Convergence Metric**: Perplexity (calculated as `exp(loss)`)

## 3. Data & Preprocessing

To emulate realistic training dynamics while eliminating non-deterministic data loading across frameworks, we leverage the actual datasets but bypass parallel dataloading randomness.

*   **Inputs**: Sampled directly from the `ImageNet100Dataset` (for ResNet50) and `OpenWebTextDataset` (for GPT-2).
*   **Shuffling & Determinism**: The PyTorch DataLoader is configured with `num_workers=0` and driven by a seeded `torch.Generator`. This guarantees that the order of the batches (the shuffled trajectory) is randomized distinctly for each seed (`42`, `420`, `4200`), but remains 100% reproducible.
*   **Augmentation**: For strict tests demonstrating exact tensor-level numerical equivalence, we pass a `--no-aug` flag. This disables stochastic transformations (e.g., RandomResizedCrop) and applies deterministic validation-style center crops to the training set in both PyTorch and TunX, ensuring exactly identical pixel-level input for a given sampled batch index.
*   **Pipeline Bridging**: The exact deterministic sequence of 1000 batches (inputs and labels) generated by PyTorch is dumped to disk and consumed step-by-step by TunX. This ensures both engines receive identical augmented data trajectories.

## 4. Hardware & Software Environment

To ensure pure FP32 mathematical equivalence and avoid non-deterministic execution in CUDA, the environment is strictly controlled:

*   **Precision Mode**: `FP32` (Single Precision).
*   **TF32 Disabling**: TensorFloat-32 (TF32) is explicitly disabled in PyTorch (`torch.backends.cuda.matmul.allow_tf32 = False`, `torch.backends.cudnn.allow_tf32 = False`) because TunX implements strict IEEE 754 FP32 math. TF32 would introduce unacceptable numerical drift.
*   **Deterministic Algorithms**: Enforced via `torch.use_deterministic_algorithms(True)` and `CUBLAS_WORKSPACE_CONFIG=:4096:8`.
*   **cuDNN Benchmark**: Disabled (`torch.backends.cudnn.benchmark = False`) to prevent the backend from auto-tuning and selecting non-deterministic convolution algorithms.

## 5. Statistical Reporting

The results of the 1000-step test are aggregated across all seeds. We report:
1.  **Loss Trajectory**: The mean loss at each step, plotted with a shaded region indicating ±1 Standard Deviation across the seeds.
2.  **Convergence Metric**: The mean Accuracy (ResNet) or Perplexity (GPT-2) with standard deviation (Mean ± Std) and confidence intervals.
3.  **Overlap Validation**: Visual and numerical confirmation that the PyTorch and TunX trajectories perfectly overlap throughout the entire 1000 steps of optimization.
