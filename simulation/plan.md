Instead of doing 2 phase topo and reverse topo which can lose information. Can you do this instead: we will just do 1 topo order macro merging BUT we will merge with different rules. If it is purely linear: X has sole dependent that is Y and Y only has X as parent, then it is safe to merge this if Y has lower cost than X (from get rank function, or in my paper I call R()). If it is a branching point, DO NOT merge yet, we only merge when hitting synchronization/joining points. If it is a synchronization/joining point, which means X has sole dependent that is Y, has no peers, and Y depends on multiple macros, then, for each pair of parent X1, X2,..., Xn, we find their common ancestor. Say X1, X2 have ancestor of A1, X2, X3 have ancestor of A2, and so on (A1 and A2 may be the same). We want to group them by nearest common ancestor. An ancestor is a branching point, which means it has multiple child operators that depends on it. We want to branch merge at those branching points/ancestors in order of the closest ones that satisfies the following rule: all children of A must synchronize at Y. We will use the old rule of branch merging: Say A1 has B1, B2,..., Bk as its children, then we find the best children Bi whose cost R(Bi) is lower than R(A1). Branch merging is also recursive, which means, it keeps merging based on branch merge condition until no more satisfies, then it (A1, A2,...) tries to contract upward with their parents since their combined macro cost might be lower. Only after we finish branch merging for all of Y's parents' ancestors do we start merging at Y's point - a joining point since it has multiple parents, we still use old rule which is opposite of branch merge strategy: we want to merge Y with the worst branch whose cost is worse than Y or, in other words, merge Y with Xi whose R(Xi) is lowest and is worse than R(Y) (there maybe none since all parents of Y can have lower cost than Y).
